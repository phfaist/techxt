# tools/ — dev-only scripts

Scripts that generate checked-in Rust source for the `techxt` library. They are
development aids: they are not part of the cargo build, are never run at compile
time, and nothing in `rust/` depends on them at runtime.

## `gen_symbols.py`

Reads pylatexenc's tables from a read-only checkout and emits checked-in Rust
statics (PLAN.md §12.4).

```sh
tools/gen_symbols.py /path/to/pylatexenc          # regenerate
tools/gen_symbols.py /path/to/pylatexenc --check  # is the committed output current?
```

Generated today (milestone M4):

| file | contents |
|---|---|
| `rust/techxt/src/defs/accents_data.rs` | the accent macros and their combining marks (from `unicode_accents_list`), the standalone form of each mark, and the (base, mark) pairs that compose under NFC |

The accent *table* is ported from pylatexenc; the composition and spacing-clone
tables are derived from the Python runtime's unicode database, because they are
pure unicode facts that `techxt` — being `no_std`, with no unicode database of its
own — has to carry precomputed.

Still to come: the `symbols_extra` long tail (milestone M8). Adding a generator is
a new `generate_<name>()` function plus an entry in `GENERATORS`; the pylatexenc
reader, the deduplicate-and-sort rule and the file writer are shared.

## Rules for generated output

- Every generated file starts with `// GENERATED by tools/gen_symbols.py — do not edit`.
- Entries are deduplicated (**last wins**, as pylatexenc's own tables resolve) and
  sorted, so that every table can be searched by bisection and every regeneration
  reads as a meaningful diff.
- Output is passed through `rustfmt` before it is written, so a regeneration never
  reintroduces a `cargo fmt --check` failure.
- Regenerated output is committed alongside the script, and re-running a script
  must produce byte-identical files unless the upstream data changed — `--check`
  is what CI or a reviewer runs to confirm it.
